Audio Encryption System

Python · cryptography · tinyec · wave · secrets

The problem

Protect an audio file's contents without giving up either speed (symmetric ciphers) or key-exchange security (asymmetric crypto) — the same trade-off TLS solves for web traffic.

What I built

A hybrid scheme: AES-256 in CFB mode encrypts the raw WAV frames directly, so it works on audio of any length with no padding. The AES key itself is protected using ECDH on the brainpoolP256r1 curve — a fresh ephemeral key pair per session, so a shared secret is derived and used to lock the key without it ever crossing the wire in the clear.

Security properties

  • Confidentiality — AES-256 encryption of the audio data
  • Key security — ECDH key exchange over an elliptic curve
  • Forward secrecy — ephemeral key pairs discarded after each session

Result & what I'd improve

Decrypted output is bit-for-bit identical to the original, confirming the pipeline is cryptographically sound end to end. It's a demo-scale build, though: key wrapping uses simple XOR rather than proper KDF (HKDF), there's no message authentication (AES-GCM would add that), and the private key is stored in plaintext for demo purposes rather than a real key store — all things I'd address before treating this as production-grade.

Secure Network Design & Implementation

Cisco Packet Tracer · Wireshark

The problem

Flat networks let a single compromised host reach everything else. The goal was to model how segmentation and access control actually reduce that blast radius in a realistic multi-department setup.

What I built

A simulated enterprise network using VLAN-based segmentation to isolate departments, with router-on-a-stick inter-VLAN routing and ACL-based least-privilege rules controlling exactly which traffic could cross between segments.

Validation

Used Wireshark packet captures to confirm the configuration behaved as intended and to identify traffic that violated the intended access policy — the same kind of check a network security review would run.

What this demonstrates

A working sense of how network architecture decisions — where you draw segment boundaries, what an ACL actually permits — directly affect how far an attacker can move laterally once they're in.
